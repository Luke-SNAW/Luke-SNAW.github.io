## 3. 분할 기준

**3.1 여는 빈도와 바뀌는 이유로 나눈다.** 규칙(03)은 매월 열고, 근거(02·04)는 전제가 바뀔 때만 연다. 같은 주제라도 "무엇을 하는가"와 "왜 그런가"를 다른 문서에 둔다.

- 03에는 규칙과 결론 한 줄만 두고, 계산은 04로 링크한다. 예: 연금 900만원 한도의 결론은 R-2.7, 계산은 T-5.
- 매도 우선순위(R-3)는 규칙이므로 03, 그 근거인 세율 표(T-1)는 제도이므로 04. 세율이 바뀌면 04를 고치고 R-3의 순서가 뒤집히는지만 확인한다.

**3.2 서로를 계속 참조하는 규칙은 한 문서에 묶는다.** 계좌별 비중(R-1)·계좌 운용 원칙(R-2)·매도 순서(R-3)·밴드와 납입금 규칙(R-4)은 하나를 바꾸면 나머지를 함께 봐야 하므로 03에 모은다.

**3.3 일회성 내용과 상시 규칙을 섞지 않는다.** 재편 이행 단계(E-1)는 끝나면 사라질 내용이라 07에 둔다. 이행이 끝나면 삭제한다 — 기록은 git 이력에 남는다.

**3.4 채택 미정인 전략은 따로 둔다.** 모멘텀 ETF와 개별주 모멘텀(05)은 채택 여부가 열려 있어 코어 규칙과 분리한다. 두 전략은 한 문서에 있지만 예산을 공유하지 않는다.

**3.5 참고 기록은 링크로 대체한다.** 제외 자산(06)은 운용 판단에 쓰이지 않으므로 본문에서 빼고 링크로만 참조한다.

**3.6 변하는 숫자는 한 곳에서만 관리한다.**

| --------------------------------------------- | ------------------------------------------ |
| 기준안 배분 비중                              | A-1 (이 문서 1장은 요약)                   |
| 평가액, 계좌별 금액·기준 비율, 연 납입금 배분 | R-1                                        |

다른 문서에 같은 숫자가 나오면 설명용 인용이며, 불일치 시 원본이 우선한다.

**3.7 수정 파급 방향.** 링크는 탐색용이라 양방향으로 걸려 있지만, **내용을 고쳤을 때 확인할 문서**는 한 방향으로 정해 둔다.

```mermaid
flowchart LR
  N[01 전체자산] --> A[02 배분 근거]
  A --> R[03 운용서]
  T[04 세금·제도] --> R
  R --> O[05 옵션]
  R --> E[07 실행·점검]
  O --> E
  X[06 제외 자산]
  R --> B[09 백테스트]
  B --> S[12 스크립트]
  R --> HN[11 Heynote 수식]
```

- 04를 고치면 → 03 → 07 순으로 확인
- 02를 고치면 → 03 → 05 → 07
- 03을 고치면 → 05·07
- 02·03을 고치면 → 09에서 재검증 여부 확인 (자동 반영되지 않음, 수동 재실행 필요)
- 06은 다른 문서의 판단에 영향을 주지 않는다
- 09도 마찬가지로 다른 문서의 판단에 영향을 주지 않는다 — 검증 기록이며 결론의 근거가 아니다.
- 12는 09의 부속이다 — 결론은 담지 않고 09의 수치를 재생성하는 코드만 둔다
- 11도 마찬가지로 다른 문서의 판단에 영향을 주지 않는다 — 03의 규칙을 계산기로 옮긴 것일 뿐, 03을 고치면 11의 상수(HN-3)를 맞춰야 하는 것은 반대 방향이다.

**3.8 문서를 추가하거나 합칠 때.** 위 기준으로 어느 문서에 속하는지 먼저 정하고, 새 문서가 필요하면 `fin.portfolio.NN-이름.md`로 만들고 새 접두어를 이 표에 추가한다. 01과 04의 병합 여부는 실제 사용 후 결정한다(미정).

**3.9 변경 이력은 문서로 두지 않는다 (2026-10-15).** 문서는 git으로 관리한다.

- **무엇이 바뀌었는지는 diff가, 왜 바꿨는지는 커밋 메시지 본문이 맡는다.** 발단, 결정, 검토했으나 택하지 않은 대안을 커밋 메시지에 쓴다.
- **앞으로도 유효한 판단 근거는 해당 주제 문서의 절에 둔다.** 특히 채택하지 않은 제안과 그 이유는 diff에 흔적이 남지 않으므로 반드시 주제 문서에 남긴다(예: R-4.3·R-4.8·R-4.14, T-5·T-6, O-1, 06).
- **개정 사유는 해당 절 첫머리의 날짜 박스로 짧게 남긴다**(예: A-3 "2026-10-13 개정").
- git 밖에서 문서만 읽는 쪽(Claude 등)은 커밋 로그를 보지 못한다. "왜"가 커밋 메시지에만 있으면 그 판단은 다음 세션에서 사라진다고 본다.
- 08 변경 이력 문서는 이 원칙에 따라 폐지했다. 그 안의 원자료 설명과 유의사항은 5장으로, 참고 문헌은 R-6과 O-1로 옮겼다.

## 4. 번호·링크 규칙

- **번호**: 문서별 접두어 + 번호. `R-4.1` = 03 문서 R-4의 1절. 헤딩은 `## R-4 …`, `### R-4.1 …` 형태로 번호로 시작한다.
- **링크**: dendron 위키링크 `[[번호|파일#슬러그]]`. 같은 문서 안은 `[[번호|#슬러그]]`. 슬러그는 헤딩 텍스트를 소문자화하고, 단어문자·공백·하이픈 외의 문자(구두점 등)는 삭제하고, 남은 공백을 하나씩 하이픈으로 바꾼 것이다 — 여러 문자가 삭제돼 공백이 연달아 남으면 하이픈도 그만큼 연달아 나온다 (예: `A-7 메가캡 고평가 문제 — SCHD의 존재 이유` → `a-7-메가캡-고평가-문제--schd의-존재-이유`, `—` 앞뒤 공백 2개가 하이픈 2개로 남는다).
- **표 안의 링크**는 레이블(번호)과 대상 사이 구분자를 `\|`로 쓴다.
- **헤딩에는** `:` `#` `|` `^` `[` `]`를 쓰지 않고, 링크도 넣지 않는다. 헤딩을 바꾸면 그 헤딩을 가리키는 링크를 함께 고친다(Obsidian의 헤딩 이름 변경 시 링크 자동 갱신 기능을 켜 두면 편하다).
- **외부 문서의 절 번호**(예: "인수인계 문서 §3-2")는 원문 번호이므로 `§` 표기를 그대로 둔다. 이 설계 문서 안에서는 `§`를 쓰지 않는다.

**모멘텀 검토 자료에서 채택하지 않은 제안**은 각 절에 사유와 함께 있다 — 절대 밴드 ±5%p(R-4.3), 분기 점검(R-4.8), 모멘텀 비중 20~30%와 연금계좌 구성안(O-1), 연금소득세 3.3~5.5% 전제(T-5), 달러계좌 SPMO(X-3), 국내 주식형·모멘텀 ETF(X-4), IRP 채권혼합형(R-2.4).

### 5.2 유의사항

- 본 문서는 대화 내용을 정리한 참고자료이며 투자 자문이 아니다
- 수치는 Yahoo Finance, PortfoliosLab, FunETF, 각 운용사 공시 기준이며 데이터 출처·측정 시점에 따라 달라진다
- 상관계수와 베타는 측정 기간에 따라 크게 변동한다. **특히 부동산 관련 상관은 평활화 편향으로 과소추정되어 있다** ([[N-4|fin.portfolio.01-net-worth#n-4-부동산의-분산-효과를-과대평가하지-말-것]]). 연도별 상관은 월 12개 데이터라 오차가 크다
- **KIWOOM 모멘텀의 장기 성과는 SPMO(달러) 대리 데이터다.** 모의 계산은 원화 환산·세금·매매비용 미반영이며, 월말 기준 MDD는 실제 장중 낙폭보다 작다
- [[N-1|fin.portfolio.01-net-worth#n-1-자산-지도]]과 [[N-3|fin.portfolio.01-net-worth#n-3-8-대-5는-목표가-아니라-현재-상태의-기술이다]]의 순자산 계산은 부동산 시세·대출 잔액이 미확정인 상태의 추정치다. 확정 후 재계산 필요 ([[E-3|fin.portfolio.07-execution#e-3-미해결-사항]])
- [[R-1|fin.portfolio.03-rebalancing#r-1-계좌-배치]]의 계좌별 금액은 2026년 9월 기준 평가액(연금저축 8,470만 / IRP 2,280만 / ISA 3,650만)으로 계산한 기준점이며, 재측정 후 갱신한다
- 보유종목·보수·지수 규정은 수시 변경되므로 매수 전 각 운용사 공식 페이지에서 확인이 필요하다
- **세제·건보료·퇴직연금·중도상환수수료 규정은 변경이 잦고 개인 상황에 따라 다르다.** 실행 전 금융기관·세무 전문가 확인을 권장한다
- 과거 수익률은 미래를 보장하지 않는다
